# LE FRAMEWORK DE HOOKS EST UN OUTIL DE LA PORTE, PAS UN EXTRA.
#
# `make test` vaut `pytest tests/unit/`, et il ramasse
# `test_installation_des_garde_fous.py`, qui lance le framework dans un
# sous-processus (`python -m pre_commit`) sur un depot jetable. Ce que la CI
# installe doit donc le contenir, et la CI n'installe que les
# `requirements*.txt` (`.github/workflows/ci.yml`) : le declarer ailleurs, c'est
# le declarer nulle part pour elle.
#
# `mesure` le 3 septembre 2026 : declare dans le seul groupe `hooks` de
# `pyproject.toml`, que rien dans la CI n'installe, l'environnement monte par le
# protocole du §2.2 rendait `make test` en `rc=2` — 3 echecs, 464 passes,
# 12 erreurs, toutes sur `No module named pre_commit` — quand un `.venv` ou
# `make install` avait passe rendait `rc=0`, 479 passes. La batterie qui garde
# l'identite ne tournait pas la ou le chantier la regarde.
#
# UN SEUL SITE, ET C'EST CETTE LIGNE-CI. `pyproject.toml` ne porte plus de
# groupe `hooks` : deux sites divergeraient sans que rien ne rougisse. La version
# est alignee sur celle du depot jumeau `rag-ingestion-pipeline`, dont le montage
# de garde-fous est porte ici — deux frameworks de versions differentes sur le
# meme poste rendraient deux verdicts.
#
# CE FICHIER NE TIRE PAS LA PILE DE PRODUCTION, et c'est ce qui autorise
# `make install` a l'installer entier. `mesure` le 3 septembre 2026, `uv pip
# install --dry-run` dans un venv nu : 39 paquets sans cette ligne, 47 avec,
# dont zero `torch` et zero `nvidia-*`. Armer un hook git ne telecharge pas la
# pile CUDA.
pre-commit==4.6.2

# PyYAML — LES JEUX DE QUESTIONS SONT EN YAML, et c'est une raison mesuree.
#
# `detect-secrets` lit un `element_id` — dix hexadecimaux derives du contenu
# d'un passage public (contrat, exigence 2) — comme une chaine hexadecimale a
# forte entropie, ce qu'elle est. Son transformateur JSON rend les elements de
# sequence ; son transformateur YAML ne rend que les valeurs de mapping. Or les
# `element_id` d'un jeu de questions vivent en elements de sequence.
# `mesure` le 8 septembre 2026, `detect-secrets-hook` v1.5.0 :
#     tests/fixtures/golden_qa_generated.json (l'ancien jeu) -> rc=1, 34 detections
#     les deux jeux en YAML de ce lot                        -> rc=0
# Le site canonique de la CAUSE est l'en-tete du jeu de questions du pipeline,
# `documentation/campagnes/2026-09-02-jeu-de-questions.yaml`, qui l'a mesuree le
# 3 septembre 2026 sur un fichier d'essai de trois chaines.
#
# POURQUOI ICI ET NON DANS `requirements.txt`. `Dockerfile.agent` ne copie que
# `src/agent` et `src/api` : aucun script de `scripts/` ne tourne dans l'image
# de production, donc rien de ce qui lit un jeu de questions n'y vit. Mettre
# PyYAML dans `requirements.txt` alourdirait l'image pour un besoin qui n'y
# existe pas. La CI installe les deux fichiers, `make test` aussi.
#
# CE QUE CELA COUTE, ET C'EST ASSUME : `yaml` etait deja present par transitivite
# (chromadb le tire), donc rien ne cassait sans cette ligne — jusqu'au jour ou
# une mise a jour de chromadb la retire. Une dependance directe non declaree est
# une panne differee, pas une economie.
PyYAML==6.0.3
