## 1. La trouvaille bloquante — la porte échoue dans l'environnement de la CI

`make test` sur la branche du lot, dans un environnement monté par le protocole
d'installation documenté — c'est-à-dire, aux outils près, ce que
`.github/workflows/ci.yml` installe :

| Cible | `main` (`d526f6a`) | Lot (`ff000f7`) | Résultat de fusion |
|---|---|---|---|
| `make lint` | `rc=0` | `rc=0` | `rc=0` |
| `make test` | `rc=0`, **461 passés** | **`rc≠0`** — **3 échecs, 12 erreurs, 464 passés** | `rc=0`, 479 passés *(avec `pre-commit` ajouté à la main)* |

Cause **unique et suffisante** : `ModuleNotFoundError: No module named
'pre_commit'`. Le harnais des tests de garde-fou invoque le framework, et le
framework n'est déclaré que dans `pyproject.toml`, groupe `hooks`, que **rien
dans la CI n'installe**. Preuve de suffisance : installer `pre-commit==4.6.2`
dans le même environnement, rien d'autre changé, rend `rc=0` et 479 passés.

**Reproduit par le pilote, dans les deux sens, sur les mêmes fichiers** : avec
l'environnement du protocole → `3 failed, 464 passed, 12 errors` ; avec le
`.venv` de l'arbre du lot → `479 passed`. Le lot avait mesuré son vert dans le
seul environnement du poste où il existait, et le pilote l'avait recopié sans
monter d'environnement propre — **c'est son erreur autant que celle du lot**.

**Et une phrase d'exhaustivité l'a autorisé.** `pyproject.toml`, sous
l'étiquette « Trois raisons, toutes mesurées », raison 3 : « la CI n'en a pas
besoin — elle appelle `make lint` et `make test` directement, jamais les hooks
git. » La prémisse est vraie ; la conclusion est fausse, parce que la CI appelle
les **tests** des hooks. C'est la forme exacte de « les deux seules façons dont
l'appel échoue » du dépôt jumeau, et elle a produit le même effet : autoriser
une régression réelle.

**Effet aggravant, mesuré :** dans cet environnement, deux tests de mutation
restent **verts pour la mauvaise raison** — ils assertent `rc != 0` et
l'obtiennent parce que l'installeur échoue faute du module, pas à cause de leur
mutation. Leur **témoin rougit et le dit** : le dispositif de témoins du lot
fonctionne comme annoncé.

## 2. Le diff de table de couverture

L'auditeur a construit sa table depuis la documentation, les docstrings et le
comportement observable, **sans lire celle du lot**, puis l'a diffée. C'est la
règle qui a produit le plus de trouvailles sur les deux dépôts : *quand un
développeur te donne une table de couverture, n'audite pas sa liste — construis
la tienne, puis diffe. Ce que ta liste contient et la sienne pas est le résultat
qui compte.*

**Sa liste : 17 + 1 tests. La table de l'auditeur ajoute 11 propriétés non
tenues**, dont une **fausse** et quatre à conséquence mesurée :

| Propriété non tenue | Conséquence |
|---|---|
| `make install` appelle réellement l'installeur | **mesurée** — la cible sort en 0 sans rien armer |
| `--inexact` ne désarme pas la porte qualité | **mesurée** — sans lui, `ruff`/`mypy`/`pytest` sont retirés du `.venv` |
| `--only-group hooks` ne tire pas la production | **mesurée** — sinon `torch` et 43 paquets `nvidia-*` |
| `--git-common-dir` : installer depuis un arbre secondaire arme tout le clone | **mesurée** — état mi-armé, mais l'installeur rougit de lui-même |
| la batterie tourne dans l'environnement de la CI | **fausse** — c'est §1 |
| `git commit --author=<interdite>` refusé | nommé dans un commentaire, asserté nulle part |
| `git merge --squash` puis commit | couvert en fait, non annoncé |
| la liste blanche contient encore l'adresse en usage | friction *fail-closed*, message trompeur |
| la configuration du dépôt déclare le contrôle | couche non protectrice, non gardée |
| `always_run: true` sur ce hook | dite « indispensable » par son commentaire, non gardée |
| `stages` contient `pre-merge-commit` | idem |

**Cause structurelle commune aux trois dernières** : aucun test n'exerce jamais
le `.pre-commit-config.yaml` **du dépôt**. Le harnais monte toujours
`repos: []` — décision correcte pour prouver l'inconditionnalité de la couche
figée, mais elle laisse la configuration réelle entièrement non gardée.

## 4. Le croisement de `--allow-missing-config` — six cellules

La décision centrale du lot : ce drapeau **n'est pas `-f`**. Vérifié dans les
deux sens, sur un bac à sable monté par l'auditeur et armé par l'installeur
**livré**, la configuration étant **commitée** à chaque état.

| Configuration | Adresse **autorisée** | Adresse **interdite** |
|---|---|---|
| présente, **déclarant** le contrôle | `rc=0`, HEAD avance | `rc=1`, HEAD immobile |
| **présente, NE déclarant PAS** le contrôle | `rc=0` | **`rc=1`**, HEAD immobile |
| absente | `rc=0`, « Skipping » | `rc=1`, HEAD immobile |

La couche figée porte le refus dans les trois lignes de la colonne interdite.

**Contrefactuel mesuré** : second bac, installeur muté pour retirer le drapeau,
configuration absente, **adresse autorisée** → **`rc=1`**, HEAD immobile, sur le
seul message « No .pre-commit-config.yaml file was found ». Avec **0 commit sur
167** portant ce fichier dans ce dépôt, le drapeau y est **indispensable**.

Le comptage du dépôt jumeau — **1 commit sur 235** sans le fichier — est
confirmé, et l'auditeur ajoute une nuance que le lot n'avait pas signalée : un
`git bisect` atteignant la racine du jumeau briquerait donc aussi, marginalement.

**Un mode d'échec non nommé, trouvé en s'y faisant prendre** : le framework
refuse tout commit tant que `.pre-commit-config.yaml` est **modifié non
indexé**. L'auditeur a produit un faux rouge avant de vérifier son harnais.

## 5. Le garde d'index lexical vaut mieux qu'il ne l'annonce

Le lot a prouvé l'exigence 5 dans un bac à sable qu'il a supprimé, puis livré un
test comme réduction rejouable. Question d'audit : *un montage qui bouchonne
trop haut rend intestable ce qu'il prétend vérifier — mute le producteur, pas le
consommateur.*

Verdict : **le test ne bouchonne pas le maillon qu'il éprouve.** La collection
factice implémente le contrat réel du store (une lecture par identifiants ne
rend que les identifiants existants) ; le code sous test est de production.

**Mutations du producteur**, et l'auditeur ne tire pas la même conclusion que le
lot :

| Mutation du producteur | rouges | le test neuf rougit-il ? |
|---|---|---|
| la recherche fabrique ses résultats au lieu de consulter le store | 1 | **oui — et lui SEUL** |
| retirer le filtre de résolution des identifiants | 1 | **oui — et lui SEUL** |
| forcer le rechargement à `False` | 6 | oui |
| l'état garde les anciens identifiants | 4 | oui |
| le filet rendu toujours faux / aveugle au retrait | 3 / 3 | non — correct, la prémisse reste vraie |
| la sonde ignore le périmé | 1 | non |

Le lot déclarait trois mutations dont une attrapée par un test préexistant.
L'auditeur montre **deux mutations dont ce test est le seul garde** —
précisément celles qui cassent le maillon « rangs lexicaux → résolution contre
le store », c'est-à-dire le mécanisme même de l'amputation. **Le lot se
sous-appelle.**

Et l'exigence 5 a été **re-prouvée sur l'agent vivant**, pas recopiée du bac
supprimé : `POST /reindex` → HTTP 200, `chunks_indexed` égal au compte de la
collection, avec et sans en-tête de clé vide comme le pipeline le fait. Les deux
moitiés s'accordent **en marche**, plus seulement à la lecture.

## 6. Ce qui n'avait pas pu être éprouvé, et l'ordre qui était faux

Simulation complète en clone jetable : fusion `--no-ff` → `rc=0`, aucun conflit
(vérifié par `git merge-tree --write-tree --messages`, **pas** par la forme qui
rend `rc=0` même en cas de conflit) ; `make install` depuis ce clone → `rc=0` ;
refus et acceptation conformes.

**La conséquence que le lot annonçait est exacte** : le `.venv` visé disparu et
aucun framework au `PATH`, tout commit d'adresse **autorisée** est refusé, HEAD
immobile, sur un message qui ne nomme ni la cause ni le remède. *Fail-closed.*

**Mais l'ordre qu'il affirmait n'est ni nécessaire ni suffisant, et le mandat du
pilote portait la même erreur.** Ce qui grave le chemin, c'est **l'arbre depuis
lequel on lance**, pas celui qu'on retire. Le pas juste est **« depuis le clone
principal »** ; le §7 du mandat prescrivait « réarmer **APRÈS** ce retrait », qui
énonce une condition qui n'est pas la bonne.

**Et un pas manquait, que personne n'avait écrit** : entre la fusion et la
réinstallation il existe une **fenêtre où tout commit du clone et de tous ses
arbres est refusé**. *Fail-closed*, mais à connaître avant d'être surpris.

## 7. Les phrases d'exhaustivité relevées

1. **« Trois raisons »** dans `pyproject.toml` — la troisième est fausse en
   conséquence, et **c'est la cause du bloquant** ;
2. **« `merge --no-ff` déclenche ces trois hooks »** — les mouchards en trouvent
   **quatre**. Sans conséquence, post-hoc ;
3. **« Les deux couches couvrent les mêmes GESTES »** — vrai des gestes, faux
   des **situations** : la couche du framework est muette dès que la
   configuration manque ;
4. **« Trois docstrings l'affirment et aucun test ne l'assertait »** — vrai de la
   propriété ; l'énumération des trois sites est fermée sans borne, et le
   scénario était déjà partiellement exercé ailleurs ;
5. **« DOUZE autres tests »** — 15 ;
6. l'énumération de **trois** gestes non couverts en oublie deux.

La décision `--allow-missing-config` est **juste et vérifiée dans les six

ni dans aucun objet atteignable, reflogs et stash compris, ni dans les
transcriptions du lot.

## 9. Les deux fois où l'auditeur s'est démenti lui-même

Consignées parce qu'elles valent mieux qu'un principe :

- il attendait que `git commit --author=<interdite>` **passe**, le contrôle ne
  lisant pas le drapeau. **Faux** : git exporte l'auteur dans l'environnement du

- une trace de mouchards attribuait à `git rebase` les hooks du commit
  préparatoire, tombé **dans** la fenêtre de mesure. Sans la seconde
  vérification, il aurait écrit que `rebase` est couvert.

*Vérifie ton harnais avant de croire ton rouge* a payé deux fois en une session.
